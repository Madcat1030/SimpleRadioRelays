# 0.2.4 delivery selection

The exact quality tie in 0.2.1 through 0.2.3 could still strand a native wired bridge. A receiver on C's near side is slightly closer to B than a Relay on C's far side, so its direct carrier can have strictly less interference despite arriving nearly exhausted.

The regression places a native receiver west of C's core, a Relay east of it, and a native transmitter north of it. A real copper wire connects receiver and transmitter. Both B-to-receiver and B-to-Relay legs are viable, and the receiver's direct interference is strictly lower by less than one point. On unchanged 0.2.3 routing, the receiver gets approximately 2.37 carrier power and the wired transmitter gets one frame, but no return packet reaches A. The report is retained in `validation/0.2.4/reproduced-on-0.2.3.xml`.

`RelayRouter` now gathers the valid direct and repeated deliveries for a recipient. `RelayDeliverySelection` finds the cleanest candidate, admits candidates no more than one interference point above it, and selects the highest arrival power. Equal power prefers cleaner actual interference, then fewer hops. The selected source is delivered unchanged, with its actual worst interference preserved.

The tolerance is inclusive and uses the cleanest candidate as its anchor. Comparing only each new candidate with the current winner could admit a chain of near-ties that drifts beyond one point, or discard a useful previous candidate after a cleaner route appears. The complete candidate set avoids both errors and makes selection independent of tower iteration order. `QUALITY_TOLERANCE` is a code constant, not a server configuration field.

Five unit tests exercise the near-tie, exact boundary, rejection beyond the boundary, all six permutations of a three-route near-tie chain, retention of actual severity, equal-power fallback and no available candidate. The native bridge test passes after the fix, requiring a regenerated receiver carrier above 1,000, one return packet and retention of the chosen route's actual worst interference.

All 21 unit tests and 25 addon Minecraft tests passed. The four native headless baseline failures match the previously captured addon-disabled control. These are environment baseline test failures with unresolved causes, not confirmed live-server bugs. The tests route synthetic encoded packets through native blocks and wires; they do not listen to decoded multiplayer audio.

The RF equations, internal minimax graph, hop budget, frame deduplication, antenna checks, component identities, inventories, saved network, card interactions, copper-wire recipes, models and text rendering remain unchanged from 0.2.3.
